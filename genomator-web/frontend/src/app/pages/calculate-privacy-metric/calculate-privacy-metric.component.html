Evaluate Synthetic Data

Upload the original VCF file and the synthetic VCF file generated for it on the Generate tab, then choose a metric to evaluate.
  • Accuracy Metric - Measures how closely the synthetic data reproduces the statistical distribution of the original data, using a sliced Wasserstein distance.
  • Privacy Metric - Measures how much private information from the original data could be inferred from the synthetic data, using unique-combination reproduction rates.
  • In-Depth Privacy Metric - A research-grade privacy/utility evaluation: DCR/NNDR (distance-to-closest-record) as the privacy metric, plus MAF/LD fidelity, across a sweep of generation parameters. This needs multiple Python environments and an external dependency well beyond what a browser tab can offer, so it runs as a downloadable local toolkit instead of on this page — see that tab for instructions.
The Accuracy and Privacy metrics above execute entirely on your own computer in your web browser; data is never transmitted outside your device. The In-Depth Privacy Metric also runs only on your own computer, as a downloadable local toolkit rather than in the browser.

This is a more thorough, research-grade privacy/utility evaluation, run across a sweep of generation parameters rather than a single result:

  • DCR / NNDR — distance-to-closest-record: how much closer synthetic individuals sit to the real training set than to a held-out real set, flagging likely memorization.
  • MAF / LD fidelity — how closely synthetic data reproduces real allele-frequency and linkage-disequilibrium structure, reported alongside privacy since the two are in tension by construction.

This needs meaningfully more than a browser tab can offer: two separate Python/conda environments, and a full sweep across many parameter settings rather than one result. So it runs as a downloadable local toolkit instead of on this page. You can still generate the synthetic data itself right here on the Generate tab, the same way as always — only the split-cohort setup and the privacy scoring happen locally.

The one rule this depends on: whatever synthetic VCF you score must have been generated from only the train half of your real cohort (step 1 below), never your full real dataset. The metric works by comparing how close synthetic data sits to individuals the generator saw (train) versus a held-out set it never saw (holdout) — if the "holdout" half was actually part of generation too, that comparison stops meaning anything, silently.
Step 1 — split your real cohort (local, one command):

Get the code from the Genomator GitHub repository, under genomator-web/privacy-evaluation/, and follow that folder's README.md to set up its two conda environments (no separate Genomator install is needed — the toolkit imports it straight from this same repository). Then split your real VCF into a train half and a holdout half it'll never see: 

python code/split_train_holdout.py your_real_data.vcf \
  --train_frac 0.5 --seed 101 \
  --out_train data/splits/split_101/train.vcf \
  --out_holdout data/splits/split_101/holdout.vcf \
  --out_audit_json data/splits/split_101/split_audit.json
Step 2 — generate synthetic data here, from the train half only:

Go to the Generate tab and upload data/splits/split_101/train.vcf from step 1 — not your original full VCF, and not the holdout file. Its N/Z/L fields map onto this evaluation toolkit's own parameter names directly: "Choose a Cluster Group Size (ie. N)" is N, "How much should rare pairs be attenuated? (ie. Z…)" is Z, "How much looseness should the process involve?" is L, and "How many Synthetic Data Points?" is how many synthetic samples you'll be scoring. Generate, then download the resulting VCF.

Step 3 — score the downloaded VCF (local):

Back in genomator-web/privacy-evaluation/, point --synthetic-vcf at the file you just downloaded instead of generating one locally: 

python code/dcr-nndr/score_one_dcr.py \
  --N 20 --Z 0.5 --L 0.6 \
  --split-seed 101 --gen-seed 1 \
  --source your_real_data.vcf \
  --splits-dir data/splits \
  --outdir data/synthetic_data/webgen_N20_Z0.5_L0.6 \
  --synthetic-vcf ~/Downloads/your_generate_tab_output.vcf \
  --py "$PY" --keep-synth

Set --N/--Z/--L to whatever you actually used in step 2 (they're recorded as a label here, not re-applied — nothing gets regenerated); --gen-seed just tells apart multiple downloaded files scored against the same split. See the README's "Using synthetic data from the web Generate tab" section for the full walkthrough, including environment setup.

Prefer to skip the website step entirely and generate locally too, e.g. for a full automated parameter sweep? The same README also covers running Genomator locally end to end via score_one_dcr.py without --synthetic-vcf, and run_cell_sweep.py for sweeping many parameter combinations at once. This replaces an earlier, simpler in-browser-adjacent check (comparing Genomator against Markov/CRBM/WGAN/RBM baselines on a single split); that tool is archived, not deleted, at genomator-web/archived-privacy-metric/ for reference.
